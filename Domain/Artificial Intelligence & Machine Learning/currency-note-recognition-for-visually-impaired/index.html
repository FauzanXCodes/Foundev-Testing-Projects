How to run the recogniser

This page has no backend. Recognition happens in the desktop script Currency Detection using OpenCV in ML/detect.py. It reads a hardcoded test image (files/test_200_1.jpg) — not your upload — so edit that line to point at your photo, then run:

python "Currency Detection using OpenCV in ML/detect.py"

The script uses relative paths (files/…), so also run it from inside that folder: cd "Currency Detection using OpenCV in ML" && python detect.py (the bundled README.md says python3 detect.py).

What it does: computes ORB keypoints on the test photo, brute-force matches them against six reference notes, keeps matches passing the Lowe ratio test at 0.789, then prints Detected denomination: Rs. … (or No Matches) and opens a matplotlib match window. Its audio playback lines (playsound, gTTS) are commented out, which is why the voice samples below are played by this page instead.

Method About the method

ORB keypoints + BFMatcher + Lowe’s ratio 0.789 — why it suits offline use
  1. ORB — cv2.ORB_create() (the script comments that it “is an alternative to SIFT”) detects oriented FAST keypoints and rotated BRIEF descriptors on the test photo and on each reference photo via orb.detectAndCompute(img, None).
  2. Brute-force matching — cv2.BFMatcher().knnMatch(des1, des2, k=2) returns the best and second-best descriptor match for every test keypoint.
  3. Lowe’s ratio test — a match is kept when m.distance < 0.789 * n.distance. The source calls 0.789 “an arbitrary number”; it filters out ambiguous matches so only distinctive texture survives.
  4. Winner takes all — the reference with the most good matches (must beat the starting threshold of 8) wins. The denomination is sliced straight from the winning path: str(training_set[max_pt])[6:-4], so files/200.jpg becomes 200, then Detected denomination: Rs. 200 is printed and cv2.drawMatchesKnn plus matplotlib draw the match map.
  5. Training set — exactly files/20.jpg, files/50.jpg, files/100.jpg, files/500.jpg, files/200.jpg, files/test_20_6.jpg. Anything below the threshold prints No Matches.

Why it suits offline, assistive use: ORB is a patent-free, CPU-only algorithm — no GPU, no network and no model weights to download. Matching against a handful of local JPEGs needs no training run, and the whole dependency list in requirements.txt is opencv-python, numpy, matplotlib and small helpers. On a phone or a low-end laptop the pipeline finishes in seconds, which is exactly what a voice-first tool for visually impaired users needs.
