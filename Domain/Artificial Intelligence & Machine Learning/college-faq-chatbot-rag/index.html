Retrieval diagnostics

How a question becomes chunks — values from .env.example and config/settings.py.

  • Hybrid blend — semantic 70% + BM25 keyword 30%; the BM25 index is rebuilt in memory at startup.
  • MMR rerank — FETCH_K=20 candidates, LAMBDA_MULT=0.5 balancing relevance against diversity.
  • Adaptive-k — if the best score is under ADAPTIVE_K_THRESHOLD=0.45, the search widens across the candidate pool.
  • Top-k — RETRIEVAL_TOP_K=5 chunks reach the prompt; chunking is CHUNK_SIZE=500 chars with CHUNK_OVERLAP=100.
  • Relevance gate — a best score below RELEVANCE_SCORE_THRESHOLD=0.20 refuses the question instead of guessing.
  • Query pipeline — normalise (abbreviation expansion) → optional LLM rewrite (ENABLE_QUERY_REWRITING=true) → retrieve.

How grounding works

  1. 1
    Retrieve

    Hybrid search (semantic MMR + BM25) pulls the top-k chunks that match the question.

  2. 2
    Gate

    If the best retrieval score is under the threshold, the pipeline returns a refusal — no answer is invented.

  3. 3
    Answer

    The LLM (temperature 0.0) answers only from the retrieved context and the response carries its sources.

Evaluation — RAGAS

python scripts/evaluate.py scores the pipeline against 8 ground-truth Q&A pairs and writes CSV, JSON and an HTML dashboard into evaluation_results/. Metrics explained — no scores are shown here because none exist until you run it:

Faithfulness
Is the answer grounded in the retrieved context?
Answer relevancy
Does the answer directly address the question?
Context precision
Are the retrieved chunks actually relevant?
Context recall
Were all relevant chunks retrieved?

PROJECT_CONTEXT.md documents a known ragas / langchain-community version caveat that can affect the evaluation script; the chat app itself is unaffected.

About

CampusWise

CampusWise is a static front-end concept for the college-faq-chatbot-rag project: a retrieval-augmented FAQ assistant for BVRIT Hyderabad College of Engineering for Women. The production chat UI in this repository is app/app.py, a Streamlit app.

The assistant answers strictly from the college knowledge base (ChromaDB vector store + OpenRouter LLM, hybrid BM25 + MMR retrieval) and refuses questions the document cannot support.

Backend status

No REST API — Streamlit only

This repository exposes no HTTP endpoints for the chat, so this page does not pretend to call one. Model-dependent actions are labelled: every send shows the run steps, and demo content carries a persistent banner.

  1. python -m venv .venv then activate it
  2. pip install -r requirements.txt
  3. Copy .env.example to .env and set OPENROUTER_API_KEY=sk-or-v1-…
  4. python scripts/ingest.py — one-time knowledge-base ingestion
  5. streamlit run app/app.py (or python run.py) → http://localhost:8501

Other real keys from .env.example: LLM_MODEL (default openai/gpt-4o-mini), EMBEDDING_MODEL, RETRIEVAL_TOP_K, RELEVANCE_SCORE_THRESHOLD, FETCH_K, LAMBDA_MULT, ADAPTIVE_K_THRESHOLD, CHUNK_SIZE, CHUNK_OVERLAP, ENABLE_QUERY_REWRITING.
