RESEARCH PIPELINE // Preis et al.–style

The actual steps encoded in this repository — data acquisition, relative-scale adjustment, feature engineering, and notebook training. No step is simulated here.

  1. 01

    PULL RAW GOOGLE TRENDS — src.data.make_dataset.Trends

    The Trends class pulls US-geo search-volume data for every keyword in src/data/keywords.txt at three periodicities, because Google Trends only serves limited windows at high resolution:

    • Daily data in 6-month increments
    • Weekly data in 5-year increments
    • Monthly data for the entire span (2004-01-01 → today, one request)

    Each increment is independently normalized 0–100, so raw slices are not comparable across time.

  2. 02

    ADJUST TO ONE RELATIVE SCALE

    adjust_weekly() anchors every 5-year weekly increment to one monthly data point, then reconstructs the weeks in between by applying each unadjusted week's percentage change to the previous adjusted value. adjust_daily() does the same for daily data, anchoring each 6-month increment to an adjusted weekly point. Finally the adjusted series is divided by its maximum and rounded to 2 decimals — producing the 0–1 Adjusted column in data/raw/* and the keyword columns in the curated CSVs.

    new_value = prev_value * (1 + unadjusted.pct_change())   # from make_dataset.py
  3. 03

    ENGINEER FEATURES — src.features.build_features

    Seven feature builders (research, delta, pct_change, sma, ema, lag, target_binary / target_bins) are applied per keyword series, then shifted 3–10 days → 272 candidate features; the top 50 by Pearson correlation with the binary target are kept (per README). See the .

  4. 04

    MAKE TARGETS — Makefile

    Reproduce the environment and dataset with the repo's real make targets:

    make requirements   # pip install -U pip setuptools wheel; pip install -r requirements.txt
make data           # python3 src/data/make_dataset.py
make lint           # flake8 src
make clean

    Honest note: the cookiecutter README mentions make train, but this Makefile defines no train target — training lives exclusively in the notebooks below.

  5. 05

    TRAIN & EVALUATE — notebooks/

    • 01-cpj-machine-learning.ipynb — MLPClassifier and XGBoost direction classifiers with a chronological train_test_split + RandomizedSearchCV hyperparameter search. Honest: this is a single hold-out split, not a rolling walk-forward loop — no walk-forward splitter appears in the notebooks.
    • 02-cpj-research-model.ipynb — replication of the Preis/Moat/Stanley Google-Trends trading signal.
    • 03-cpj-visualisation.ipynb — plotting/exploration.

    The README reports a strategy backtest comparing the MLP against 10,000 random simulations (mean ± 1σ band) and buy-and-hold; best reported annual returns: MLP 91.3%, XGBoost 44.2% (2008→present, heavily influenced by the COVID crash per the README).

⚠ SERVING REALITY CHECK

This repository ships no model weights, no serialized estimators, and no prediction API/server. Producing a live direction prediction requires training the MLPClassifier / XGBoost models inside the Jupyter notebooks on your own machine. Everything in this terminal is data + pipeline documentation only.
