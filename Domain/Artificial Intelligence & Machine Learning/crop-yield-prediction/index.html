Prediction requires the local pipeline

This repository has no HTTP server and no trained weights. “Run prediction” cannot execute here. A real forecast needs:

  • Google Earth Engine credentials — earthengine authenticate, then verify with python -c "import ee; ee.Initialize()"
  • Roughly 110 GB of storage for the MODIS export of the top 11 soybean states (processed files alone are ~97 GB)
  • The engineered histogram data/img_output/histogram_all_full.npz — absent from this repository; produced by the engineer stage
  • The conda environment: conda env create -f environment.yml, then conda activate crop_yield_prediction

Then run the four stages below in order from the project root.

  1. 1

    Export MODIS imagery from Earth Engine to Google Drive

    python run.py export

    All bands for a county across export years are concatenated to reduce file count; supports checkpointing via check_if_done=True.

  2. 2

    Process split by year, merge tif files, apply farmland mask

    python run.py process

    Writes .npy files to data/img_output (~97 GB); delete_when_done=True removes the original tif files as it goes.

  3. 3

    Engineer build per-county reflectance histograms

    python run.py engineer --num_bins 32

    9 bands × 32 bins, capped at max_bin_val=4999 → histogram_all_full.npz, the models' input.

  4. 4

    Train fit CNN or RNN, optionally with the deep GP

    python run.py train_cnn --use_gp True

    Models save to data/models/<model_type> with per-year result CSVs. With use_gp=True the non-GP results are also kept for analysis.

About the method

Facts below are taken from the repository README, run.py and data/README.md.

The paper

This repository is a PyTorch implementation of Jiaxuan You's 2017 project: Deep Gaussian Process for Crop Yield Prediction Based on Remote Sensing Data (AAAI 2017). The work won the Food Security category of the World Bank's 2017 Big Data Innovation Challenge. It predicts soybean yields in US counties.

The nine MODIS bands

Satellite input comes from MODIS aboard NASA's Terra satellite. Three products are combined:

  • MOD09A1 (surface reflectance) — spectral reflectance for bands 1 through 7, effectively a multi-spectral image of the county.
  • MYD11A2 (land surface temperature) — two additional bands used as model input.
  • MCD12Q1 (land cover type) — used as a mask so that only farmland pixels are considered.

Seven reflectance bands plus two temperature bands give the in_channels=9 used by both models. The engineer stage turns each county-year image into a histogram over these bands (num_bins, default 32; max_bin_val=4999).

Deep Gaussian Process & uncertainty

Deep Gaussian Processes combine the expressivity of deep neural networks with a Gaussian Process's ability to leverage spatial and temporal correlations between data points — neighbouring counties and neighbouring years inform each other. When use_gp=True (the default in run.py), the GP sits on top of the network's features, and the pipeline also saves the plain non-GP results for analysis.

The GP kernel hyperparameters exposed in run.py: length scales for location (r_loc=0.5) and year (r_year=1.5), noise variance sigma_e=0.32, parameter variance sigma_b=0.01, kernel variance sigma=1.

Pipeline & data requirements

The entry point is run.py (Python Fire). Four stages — export, process, engineer, train — each read the previous stage's files from the data folder. USDA yield data (yield_data.csv, bushels per acre) and county centroids (county_data.csv) ship with the repo; the MODIS imagery must be exported from Earth Engine yourself (~110 GB for the paper's top-11-states setting, major_states_only=True).
